# Cross-Processor Comparison

This compares only the requested base `CV32E40P` and `CVA6` models. It does not merge their bottleneck mechanisms.

| Aspect | CV32E40P | CVA6 | Shared or different? | Implication for bottleneck analysis |
|---|---|---|---|---|
| Pipeline stages | 4 stages: `IF_stage -> ID_stage -> EX_stage -> WB_stage` (`CV32E40P.corePerfDsl:48-55`) | 7 top-level stages: `PC_stage -> IF_stage -> IQ_stage -> ID_stage -> IS_stage -> EX_stage -> COM_stage`, with IF and EX subpipes (`CVA6.corePerfDsl:73-116`) | Different | CV32E40P attribution is coarser; CVA6 needs queue, issue, subpipe, cache, and commit attribution. |
| Branch handling | Static predict-not-taken via `common::StaticBranchPredictModel` (`StaticBranchPredictModel.cpp:35-52`) | Dynamic BHT/BTB/RAS predictor via `cva6::BranchPredictionModel` (`BranchPredictionModel.cpp:57-267`) | Different | Branch fields must be processor-specific: CV32E40P needs static predicted/actual result; CVA6 needs predictor component and target metadata. |
| Data dependency handling | `StandardRegisterModel` source/destination readiness in ID flow | Same shared register model, used in issue-stage source readiness | Shared class, different pipeline placement | RAW waits should be computed separately because CV32E40P waits in/around ID, while CVA6 waits in IS/issue. |
| Scoreboard/clobber | No explicit scoreboard/clobber model found for base CV32E40P | `ClobberModel` plus `uA_Issue`, `uA_Clobber`, `uA_OF_A/B` in `IS_stage` | Different | CVA6 needs clobber/commit dependency fields; CV32E40P should not report this as present. |
| Memory/cache modeling | Load/store use `LSU`, `DPort_R`, `DPort_W`; no CV32E40P cache model found | I-cache model and D-cache model with hit/miss/non-cacheable delays | Different | CV32E40P memory attribution is port/resource-level unless a cache model is added; CVA6 can separate I-cache and D-cache potential delays. |
| Functional units | ALU, CSR, LSU, `MUL`, `MULH(5)`, variable `DIV`/`DIVU` | ALU, two-stage MUL, variable DIV/DIVU, load/store subpipes; FPU/CSR appear in `llm_output/CVA6_QWEN.corePerfDsl` but not base `CVA6.corePerfDsl` | Different | CVA6 needs subpipe and block attribution; CV32E40P mainly needs simple FU and divider latency attribution. |
| Resource conflicts | Stage/resource max timing, D/I ports, multiplier/divider resources | Capacity buffers and explicit subpipe blocks: MUL blocks ALU, DIV blocks ALU and MUL (`CVA6.corePerfDsl:97-103`) | Different | CVA6 structural-resource bottlenecks need more detailed instrumentation than CV32E40P. |
| Instruction groups | `Arith_Ra_Rb`, `Arith_Ra`, `Arith_X`, `Mul`, `MulH`, `Div`, `DivU`, CSR, Load, Store, Branch, jumps | `Arith_0`, `Arith_Rs1`, `Arith_Rs1_Rs2`, Branch, Jump, JumpR, Mul, Div, DivU, Load, Store | Different | Do not aggregate by one generic instruction taxonomy without processor-specific mapping. |
| Trace fields | `rs1`, `rs2`, `rd`, `pc`, `brTarget`, `rs2_data` | `rs1`, `rs2`, `rd`, `pc`, `brTarget`, `imm`, `rs1_data`, `rs2_data`, `addr` | Partially shared | CVA6 has enough fields to feed branch/cache/divider models; CV32E40P lacks `addr`, `imm`, and `rs1_data`. |
| Timing trace fields | `IF_stage`, `ID_stage`, `EX_stage`, `WB_stage` from `CV32E40P_PerformanceModel.cpp:78-87` | `PC_stage`, `IF_stage`, `IQ_stage`, `ID_stage`, `IS_stage`, `EX_stage`, `COM_stage` from `CVA6_PerformanceModel.cpp:110-123` | Different | CVA6 top-level timing is richer but still hides substage/subpipe causes. |
| Likely potential bottleneck categories | RAW, static branch redirect, divider latency, memory port/LSU, multiplier latency | I-cache/frontend, dynamic branch prediction, RAW, clobber/commit, D-cache, EX subpipe conflicts, divider latency | Different | Reports must stay separate; only category names are shared. |
| Missing instrumentation | Stage enter/exit, stall reason, RAW producer id, branch result/redirect, memory address/cache fields, resource wait | Stage/substage enter/exit, predictor result/target, cache hit/miss/delay, clobber producer id, subpipe/resource wait, commit occupancy | Partially shared gaps | A common schema can be used, but processor-specific producers must populate different fields. |
| Tunable/model parameters | `MULH(5)`, divider formula; no cache parameters found | I-cache delay 1/5, D-cache delay 1/7/9, BHT/BTB/RAS sizes, EX/COM/IQ capacities, divider formula | Different | CVA6 has more tunables to surface in sensitivity analysis; CV32E40P has fewer static parameters. |
| Uncertainty | Adjacent `CV32E40P_CORE`, `CV32E40P_LLM`, `CV32E40P_QWEN_1` variants exist but are not the base model | Adjacent `CVA62`, `CVA6_QWEN_1` variants exist; `llm_output/CVA6_QWEN.corePerfDsl` has CSR/FPU not in base `CVA6.corePerfDsl` | Shared uncertainty pattern | Keep base models separated from adjacent generated variants unless explicitly selected. |
